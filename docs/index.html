Knowing when to ask a human

A bank's chatbot has to sort each customer message into one of 77 intents. Why do classical classifiers get some of these wrong, and when should they hand the message to a person instead of answering? This study tests four pre-registered hypotheses on BANKING77, using only methods from the course.

1The question

A wrong answer from a support bot costs more than a polite "let me connect you to someone". So accuracy alone isn't the right target. We also want to know which messages the model will get wrong, and whether its confidence tells us in advance. The hypotheses were written down and committed before any model was trained (PREREGISTRATION.md):

H1Most errors come from overlapping intent definitions, not from a weak model.SUPPORTED

3Data

BANKING77 (Casanueva et al., 2020): 13,083 short customer messages to a bank, each labelled with one of 77 intents such as card_arrival or exchange_rate. There are 10,003 training and 3,080 test messages. Training intents have 35 to 187 examples each (median 127), and the test set has 40 per intent. The data is downloaded at a pinned commit and checked with SHA-256, so every run sees the same bytes.

Cleaning the training split

  • 4 exact duplicates removed, leaving 9,999 messages.
  • 153 near-duplicate pairs (TF-IDF cosine ≥ 0.90) are grouped, so a pair never straddles two folds. Otherwise the model would "see" a held-out message during training and the CV score would be inflated.
  • 10 intents are held out at random (seed 2026) for the unseen-intent test.

A first hint of H1

Some near-duplicates carry different labels:

"has my top up gone through?"pending_top_up
"has my top-up gone through?"top_up_reverted
"how can i get new card?"contactless_not_working
"can i get a new card?"order_physical_card

No model can get both of these right. The label set itself overlaps.

4Features and methods

Preprocessing

Text is lowercased and whitespace is collapsed. Two TF-IDF views are concatenated: word 1–2 grams (words of 2+ characters) and character 3–5 grams inside word boundaries, which helps with typos like "recieved". Term counts are damped with 1 + log(count), and each view is L2-normalised. Every learned step (vocabulary, IDF, SVD, scaling) sits inside an sklearn Pipeline, so it is refit on the training folds only.

Hyperparameters are chosen with the one-standard-error rule: take the simplest setting whose CV score is within one standard error of the best. For M1 that gave word + char features with C = 10. A small neural network and gradient boosting were planned as optional extras and dropped for time. Both are stated in Limitations.

5Evaluation design

  • Pre-registered. Hypotheses, pass criteria, split rules, and constants were committed before training. Two later changes were added as dated amendments, each before the numbers it affects were computed.
  • 5-fold StratifiedGroupKFold (stratified by intent, grouped by near-duplicate cluster). Every tuning choice, threshold, and hypothesis decision uses out-of-fold predictions.
  • The test set is opened once. Only one script may read it, a test enforces that, and a lock file blocks a second run. It ran on commit c21163f, after a full dry run on a training fold.
  • Macro-F1 is the main metric, so all 77 intents count equally.
  • 95% bootstrap CIs (1,000 resamples) on every headline number. Model comparisons use paired bootstraps.
  • Calibration: expected calibration error (ECE), 15 bins.
  • Handoff: risk–coverage curves, their area (AURC), and an explicit cost: a wrong answer costs k, a handoff costs 1.
  • Robustness: 5 fold seeds (SD 0.002) and a stricter near-duplicate grouping (−0.0008).

6Results: how good are the models?

Cross-validated (out-of-fold, 9,999 messages) and on the held-out test set (3,080 messages, run once). The test score is slightly higher than CV. That's expected: the final model trains on all the training data instead of 80% of it, and the learning curve predicts about that gain. Removing the 134 test messages that nearly duplicate a training message changes test macro-F1 by only 0.002.

7H2: when to hand off SUPPORTED

Rule: answer if the model's top probability is at least a threshold, otherwise hand off. Drag the threshold and see what happens to how many messages get answered, how accurate those answers are, and the total cost. The random line is what you'd get by handing off the same number of messages at random (B2). Its error never improves.

What the test shows

At every pre-registered coverage level from 50% to 95%, the 95% CI of (confidence error − random error) is below zero, in CV and on the test set. The area under the risk–coverage curve is 0.018 vs 0.099 for random (CV) and 0.015 vs 0.087 on test.

The thresholds were chosen on CV only (0.228, 0.560, 0.685 for k = 2, 5, 10). On the test set each one lands within 0.01 of the best cost achievable there.

Can a second model do better? (E1)

E1 is slightly better and the CIs on the gain exclude zero, but most of the signal is already in the top probability.

8H3: accurate is not the same as calibrated SUPPORTED

A model is calibrated if, among messages where it says 80%, about 80% are right. Pick a model to see its reliability diagram. Bars below the diagonal mean overconfident, bars above mean underconfident.

The most accurate model (M1-L2) has an ECE of 0.107 in CV, about twice that of the L1 model (0.058), and the CIs don't overlap. L2 is underconfident: it says 79% on average but is right 90% of the time. With 77 classes, an L2 penalty spreads probability over many similar intents. That's harmless for ranking, which is why H2 still works, but it means the raw probability shouldn't be read as a literal chance. The random forest is the extreme case (ECE 0.47): averaging 300 trees' votes over 77 classes flattens every probability.

9H4: how many dimensions does the signal need? SUPPORTED

Truncated SVD compresses ~37,000 TF-IDF features into d directions, fit on the training folds only. Then logistic regression is trained on those directions.

d = 100 keeps 93.8% of the full model's macro-F1 (93.9% on test), while explaining only 34% of the TF-IDF variance. The intent signal lives in a few directions, and most of the variance is noise for this task. The full model is still best, so SVD is a compression, not an improvement.

10H1: why the errors happen SUPPORTED

Two intents are linked if the model confuses them at least 5 times (the pre-registered rule), and linked intents form confusable groups. If errors were mostly caused by a weak model, they would be spread out. Instead they concentrate inside these groups.

Errors only (the diagonal is hidden). Rows are the true intent, columns the prediction. Intents are ordered by group, so the dark blocks on the diagonal are the groups. Hover a cell for details.

Caveat, stated openly: at threshold 5, one group chains 29 intents through shared neighbours, and the share falls below half at stricter thresholds. At every threshold, though, errors fall inside groups far more often than chance.

(b) 50 errors, labelled by hand

(c) Different models, same mistakes

Of logistic regression's 10 most-confused pairs, 6 are also in KNN's top 10 and 7 in the random forest's. Very different model families trip on the same pairs, which points at the labels rather than at any one model.

11Unseen intents (exploratory)

Real customers ask things no intent covers. To simulate this, the main model was retrained on 67 intents with 10 held out entirely, then shown messages from the missing 10. It has to pick a seen intent, so the only defence is low confidence. Use the Unseen intents tab in the H2 slider to see the confidence distributions.

Mean confidence is 0.80 on seen intents vs 0.43 on unseen ones (AUROC 0.855 in CV, 0.882 on test). At k = 5, 70% of unseen messages are handed off vs 16% of seen ones. The weak spot is an unseen intent with a close seen neighbour: "wrong exchange rate for cash withdrawal" looks like "card payment wrong exchange rate", so only 35% of it is caught.

12Learning curve: would more data help?

Nested, stratified subsets with 5 random draws per size, scored on the same held-out folds (and on the test set with the full training data). With just 5% of the data (about 440 messages) the model already matches the keyword rule trained on everything. The curve is still rising at 100%, so more labelled data would likely help. Together with H1, though, the ceiling is set by the overlapping labels, not by data volume.

13Limitations

  • One dataset, one domain, English only. Results may not carry over to other banks or languages.
  • A balanced test set (40 per intent), unlike real traffic where a few intents dominate.
  • One intent per message. Messages that really carry two requests are forced into one.
  • The cost ratio k is assumed, not measured. That's why the slider lets you change it.
  • The coarse groups and the 50 error labels are the author's own judgments, and 50 is a small sample (95% CI for "ambiguous label" ≈ 52–78%).
  • The H1 grouping chains into one large group at the pre-registered threshold. Sensitivity thresholds are reported alongside it.
  • The unseen-intent test covers only the 10 intents drawn, and is exploratory.
  • Course methods only: no pretrained embeddings or transformers, which would likely score higher. A small MLP and gradient boosting were dropped for time.

14Conclusion

A well-tuned linear model on TF-IDF gets 0.913 macro-F1 on BANKING77, far above a keyword bot. Its remaining errors are mostly not "the model is too weak": they concentrate in groups of intents whose definitions overlap, and merging those groups lifts accuracy from 91% to 96.5%. The model's confidence, although underconfident in absolute terms, ranks its own mistakes well. A threshold chosen in cross-validation answered 85% of test messages at 97% accuracy and handed off most messages from intents it had never seen. The practical advice: fix the label set first, and let confidence decide when to call a human.
